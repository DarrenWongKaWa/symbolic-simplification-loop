\section{Executive Summary}

This report is the human-readable WEP Capability Report for TASK\_052.
WEP (Workflow Execution Protocol / Work Execution Protocol) is the
project-local construction-loop workflow defined under
\texttt{docs/dev/construction\_loop/} and authorized by the main safety
policy in \texttt{docs/safety.md}. The Capability Auditor inspected the
repository as of HEAD \texttt{98a2040 TASK\_041 add report schema
checker} and recorded, with evidence, what the construction loop can do
today, what it cannot do yet, and what remains unproven.

The headline conclusion is conservative: the construction loop is a
checker-assisted prompt-loop at most, with L2 partial automation level
and no unattended runner. Loop-engineering remains probe-only and may
not modify the main repo. Scientific and runtime files remain protected
and are out of WEP authority.

\section{What WEP Can Do Now}

\subsection{Human-followed protocol}

WEP can be carried out by a human or single-session agent that
faithfully follows the role cards. Specifically:

\begin{itemize}[leftmargin=2em]
  \item Run the four startup commands and record them.
  \item Read \texttt{docs/safety.md} and
        \texttt{docs/dev/construction\_loop/reporting\_convention.md}
        and apply them.
  \item Write the bounded artifacts in the canonical
        \texttt{reports/TASK\_XXX\_<NAME>/} directory.
  \item Run the two bounded checkers
        (\texttt{check\_forbidden\_paths.py} and
        \texttt{check\_task\_report\_schema.py}) on the worktree.
  \item Hand off to the next role via the executor report or
        conversational handoff.
\end{itemize}

\subsection{Machine-checkable protocol}

The following are machine-checkable today, on demand, by a human:

\begin{itemize}[leftmargin=2em]
  \item \textbf{Forbidden dirty paths} via
        \texttt{python3 scripts/check\_forbidden\_paths.py}.
  \item \textbf{Report directory shape} via
        \texttt{python3 scripts/check\_task\_report\_schema.py
        reports/TASK\_XXX\_<NAME>/}.
\end{itemize}

\subsection{Automation not yet implemented}

WEP cannot, today, automatically:

\begin{itemize}[leftmargin=2em]
  \item pick the next bounded task;
  \item invoke Planner, Executor, Reviewer, or HumanIntegrator;
  \item merge or vendor loop-engineering;
  \item commit, push, merge, reset, rebase, cherry-pick, freeze,
        or sign off;
  \item touch \texttt{sigma\_abc/}, \texttt{checkpoints/}, signoff
        ledgers, or scientific/runtime files.
\end{itemize}

\section{What WEP Cannot Do Yet}

\begin{itemize}[leftmargin=2em]
  \item Cannot automatically select and safely execute the next task.
  \item Cannot automatically call Planner / Executor / Reviewer /
        HumanIntegrator.
  \item Cannot prove semantic or scientific correctness of any patch.
  \item Cannot replace the verifier, the checkpoint, or human signoff.
  \item Cannot let loop-engineering directly modify the main repo.
  \item Cannot unattended commit, push, or merge.
  \item Cannot safely touch \texttt{sigma\_abc/}, \texttt{checkpoints/},
        signoff files, or runtime files by WEP alone.
  \item Cannot guarantee Codex or Claude Code is in the correct worktree
        unless each session performs the four startup commands and
        records them.
  \item Cannot enforce the role-card schema, because the schema file
        does not yet exist.
  \item Cannot enforce the file-location contract, because the contract
        file does not yet exist.
  \item Cannot maintain the task index, because
        \texttt{tasks/TASK\_INDEX.md} does not yet exist.
\end{itemize}

\section{Automation Level Assessment}

The levels used by this report are:

\begin{itemize}[leftmargin=2em]
  \item \textbf{L0} --- human-only docs protocol.
  \item \textbf{L1} --- human-gated prompt-loop.
  \item \textbf{L2} --- checker-assisted prompt-loop.
  \item \textbf{L3} --- local semi-auto runner, no auto-commit.
  \item \textbf{L4} --- CI-assisted runner.
  \item \textbf{L5} --- unattended automation.
\end{itemize}

\textbf{Conservative assessment: L2 partial.}

Two checkers exist and can be run on demand. There is no local runner,
no agent-bus integration, no GitHub Action, and no unattended loop. The
role cards and reporting convention are docs-only and require humans to
follow them. The audit does not rate L3 or above because no repo-local
runner exists and none is authorized.

\section{Loop-Engineering Status}

\begin{itemize}[leftmargin=2em]
  \item \textbf{Can loop-engineering be used now?} \\
        No, probe-only.
  \item \textbf{Can it run in a probe worktree?} \\
        Yes, probe-only. No probe worktree exists in the main repo.
  \item \textbf{Can it modify main?} \\
        No. The denylist in \texttt{docs/safety.md} and the master
        repair framework forbid vendoring and submodule inclusion.
  \item \textbf{Can it replace WEP?} \\
        No.
  \item \textbf{Can it replace verifier / signoff / checkpoint?} \\
        No.
  \item \textbf{Can it be used as audit / cost helper?} \\
        Yes, but only inside an approved wrapper, e.g.
        \texttt{scripts/run\_loop\_engineering\_audit.py}, which does
        not yet exist (TASK\_045).
  \item \textbf{What wrapper / checker is still needed?} \\
        A repo-local audit wrapper that confines loop-engineering to a
        probe worktree, refuses forbidden-path dirt, and captures its
        output to a canonical \texttt{reports/TASK\_XXX\_<NAME>/} path.
\end{itemize}

\section{Safety Boundaries for Scientific / Runtime Files}

\textbf{WEP alone does not authorize scientific or runtime edits.}

Scientific and runtime edits remain under the verifier, the reviewer,
the checkpoint, and human signoff. WEP may document, audit, and propose
human-readable supplements, but it may not edit:

\begin{itemize}[leftmargin=2em]
  \item \texttt{sigma\_abc/}
  \item \texttt{checkpoints/}
  \item scientific output files
  \item validation summaries and completion matrices
  \item \texttt{.loop/human\_signoff.yaml} and other signoff ledgers
  \item \texttt{agent\_bus/}, \texttt{loop\_engine/}, \texttt{schemas/}
\end{itemize}

Future scientific / runtime work must come through a bounded,
human-approved task that explicitly names verifier, reviewer,
checkpoint, and signoff constraints.

\section{Caveats / NOT\_PROVEN Items}

\begin{itemize}[leftmargin=2em]
  \item No WEP Capability Auditor role card existed before TASK\_052.
        The one created here is the canonical role card; do not
        duplicate under another name without a bounded task.
  \item No \texttt{docs/dev/construction\_loop/role\_card\_schema.md}
        exists at audit time. Field coverage of role cards relies on
        convention, not a machine-checkable schema.
  \item No \texttt{docs/dev/construction\_loop/file\_location\_contract.md}
        exists at audit time. Path discipline relies on the role cards,
        the safety policy, and the reporting convention.
  \item The report-schema checker currently requires four core
        artifacts (\texttt{PLAN.md}, \texttt{executor\_report.md},
        \texttt{review\_result.json}, \texttt{landing\_report.md})
        while \texttt{reporting\_convention.md} and the repair
        framework list seven minimum files. This mismatch is recorded
        here as a caveat. The audit does not repair it.
  \item The PDF / LaTeX content quality is not validated by any
        checker. The auditor compiles the LaTeX on the host and
        records the build outcome, but does not lint the content.
  \item Semantic or scientific correctness is not provided by WEP.
        WEP does not replace the verifier, the reviewer, the
        checkpoint, or human signoff.
  \item Loop-engineering remains probe-only. This audit does not rate
        any loop-engineering capability as \texttt{IMPLEMENTED}.
  \item \texttt{WEP} is a project-local phrase. The auditor expands it
        in this report as Workflow Execution Protocol / Work Execution
        Protocol, but does not claim that WEP is an external standard.
\end{itemize}

\section{Conclusion}

The construction loop has a documented protocol, a canonical reporting
convention, two bounded checkers, and a small number of in-flight
documents (safety policy, reporting convention, repair framework). It
does not have a runner, an agent bus, a GitHub Action, a Langflow
integration, a role-card schema, a file-location contract, or a task
index. The conservative conclusion is that WEP is an L2 partial
checker-assisted prompt-loop, that loop-engineering is probe-only, and
that scientific and runtime files remain protected.
